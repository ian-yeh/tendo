tendo
GitHub npm Docs

Browser eyes and hands for coding agents.

Tendo captures what a web page looks like (screenshots, an element map, console and network errors) and clicks or types on it by element id. It ships no LLM. Your agent does the looking and the thinking; Tendo sees and acts. No API key, no config.

$ npx -y @ianyeh/tendo look <url>

Node 22.12+. Chromium is fetched on first use.

Give your agent the skill

The skill teaches Claude Code, Codex, and friends when and how to reach for tendo. That is the whole setup.

$ npx skills add ian-yeh/tendo --skill tendo -g

Drop -g to install for the current project only.

Every act returns the new page state, never a bare "Done". Targets are an element id from the last capture or a plain-language clause. If the page changed, you get not_found or ranked ambiguous candidates instead of a wrong click.

When to use it

On clean semantic HTML, a plain DOM tool is cheaper. Tendo earns its keep when the DOM is not the whole story:

  • Canvas, WebGL, video. Charts, maps, games, design tools. Nothing to select, only pixels.
  • Visual checks. Does the total render, line up, have enough contrast, and stay put on load.
  • Getting to a starting state. --after "type email, click sign in" primes a page in one call.
  • Long sessions. --session <id> keeps the browser alive between agent turns, reaped after 10 minutes idle.

Commands

look <url>
Capture page state: screenshots on disk, element map, diagnostics. Climb from --text-only to --annotate only when you need pixels.
act <url | --session id> <action>
Run one grounded action and return the new page state.
sessions
List live browser sessions and their idle TTL.
kill <id> | --all
Close one session or all of them.
